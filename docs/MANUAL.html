01 / SETUP

起動はダブルクリックだけ

必要なものは Python 3.8以上。アプリも元のPyBotも、LLM・GPU・外部APIキー・pipライブラリを使いません。初回だけ固定版PyBotのソース取得にインターネット接続が必要です。

MAC

Macで起動

start_mac.command

ダウンロードしたZIPを展開し、このファイルをダブルクリックします。保護機能にブロックされた場合は、右クリック→「開く」で内容を確認して実行します。

ターミナルからは python3 launch.py でも起動できます。
WINDOWS

Windowsで起動

start_windows.bat

ZIPを展開し、このファイルをダブルクリックします。Python launcher（py）を優先し、なければpythonコマンドを使います。

ターミナルからは py -3 launch.py でも起動できます。
初回の動き： アプリが huggingface/pybot の固定コミットを取得し、.runtime/pybot に保存します。次回以降は再ダウンロードせず、ローカルで使えます。初回にダウンロードできない場合、既存の公式PyBotを環境変数 PYBOT_DEMO_SOURCE で指定できます。
02 / SCREEN TOUR

どこを見ればよい？

左半分は会話、右半分は回答生成の観察です。右パネルのタブを変えれば「候補」「コード」「内部構造」「議論」を順番に見られます。

01 · PLAYGROUND

質問する

左下の入力欄でEnterを押します。Shift+Enterなら改行できます。初回だけPyBotの大量のPythonを読み込むので時間がかかることがあります。

02 · CANDIDATES

候補を比べる

右側にモジュール名、PRIORITY、各候補の内容、採択された回答が表示されます。応答時間も実測値です。

03 · SOURCE

ルールを読む

候補をクリックすると、実際の bot/modules/*.py が開きます。ソース検索からもコードに飛べます。

03 / LIVE PLAYGROUND

まずは3つの実験

EXPERIMENT 01 · MEMORY

名前を覚える？訂正できる？

Hi, I'm Sam.
What's my name?
Actually, my name is Alex.
What's my name now?

会話中の名前が記憶されたか、訂正後に更新されたかを確かめます。「メモリの状態を調べる」で、処理前後の保存項目も見てください。

EXPERIMENT 02 · GENERALIZATION

言い換えに強い？

How long should I boil an egg?
What's the best way to cook eggs in water?

意味が近くても、候補を出すモジュールの組み合わせが変化する可能性があります。まず予想してから比較します。

EXPERIMENT 03 · UNKNOWN CONCEPT

未知の概念と他言語は？

Explain Quantum Banana Regression.
こんにちは。私の名前は太郎です。

架空概念や英語以外の入力に対して、既存ルールがどう振る舞うかを見ます。出力がもっともらしくても、正確だとは限りません。

04 / TRACE & CODE

「この返答は、どこから来たのか」

1

PyBotに質問し、右側の候補を確認します。

2

調べたい候補をクリックして「ソース追跡」を開きます。対応するPythonファイルに移動します。

3

「実行行を追跡」を押します。会話を同じseedで別メモリに再実行して、選択した候補モジュールと arbiter.py の通過行を採取します。

4

緑の実行行、関数呼び出し一覧、元の返答との一致・不一致を観察します。疑問を持った行は元ファイルをGitHubで開けます。

発展：もっと深いコード探索　「回答モジュール」と「回答選択器 arbiter.py」を切り替え、両者の処理を比較できます。「実行された関数とその回数」を開くと、回答モジュールから呼び出された補助関数の一覧も表示され、クリックでその定義位置へ移動できます。関数の呼び出しを観測したことと、関数内部のすべての実行行を観測したことは別です。さらに連続する2つの質問では、回答候補となったモジュール集合の重なりを表示します。これは回答内容の意味的類似度ではありません。
重要：二つの証拠の種類を分けてください。

「候補・優先度・採択・時間」は元の質問の実測値です。一方「通過行」は再実行の観測値です。再実行結果が違えば、元の会話と同一経路だとは断言できません。また、行を通った事実だけで採択の因果理由を確定することもできません。

PRIORITY はニューラルネットの確率・確信度ではなく、回答モジュールの優先度です。採択は、優先度以外の規則を使う arbiter によって決まります。

05 / WORKSHOP

勉強会45分の進め方

00–10分

PyBotの全体像

observe → respond → arbiter → after。内部構造タブで「どこで会話らしさが生まれるか」を予想する。

10–20分

ライブ実験

挨拶と記憶、言い換え、未知の概念を試す。候補件数や採択モジュールを記録する。

20–35分

コード解剖

候補と優先度を比較し、実行行を追跡。異なる結果をもたらした条件分岐を探す。

35–45分

ルールベースとLLMの未来

汎化、解釈性、保守コスト、安全性、計算コストを議論。別のLLMに同じ質問をして比較してもよい。

初心者向け

「理解しているように見える」理由

大量の辞書・条件分岐・会話メモリと、複数候補から一つを選ぶしくみに注目。言葉を少し変えて同じ結果になるか、会話をリセットしても同じ答えか、手を動かして観察します。

上級者向け

汎化・規則競合・説明可能性

未知入力への一般化、選択器の衝突解決、メモリ構造、優先度と意味的一致、ベンチマークへの過適合などを評価。学習済み重みを使うLLMとの根本的な違いを議論します。

観点PyBot（ルールベース）LLM
回答の生成明示された規則と候補選択学習済みの重みから次トークンを推定
会話の記憶キーやデータ構造で記憶主にコンテキスト内の情報から応答
未知表現既存規則で扱える範囲に依存分布的な一般化が可能（誤答もある）
観察しやすさ候補・実行行を追跡しやすい内部表現と回答理由の対応は複雑
主な課題ルールの網羅性・競合・保守幻覚・計算資源・説明可能性

参考：PyBot公式リポジトリ、SmolTalkBench。公式READMEの勝率26%は特定の評価条件での結果であり、一般的な推論力が同等という意味ではありません。

06 / TROUBLESHOOTING

よくある問題

起動時にPythonが見つからない

Python公式サイトから3.8以上をインストール。WindowsではPATH登録を有効にしてください。

ネットワークでPyBotのダウンロードに失敗する

初回はcodeload.github.comから固定版ソースを取得します。企業ネットワークの制限下では、公式PyBotを別途入手し、環境変数 PYBOT_DEMO_SOURCE でフォルダを指定してください。

最初の回答まで時間がかかる

PyBot本体は大量のPythonファイルを読み込みます。初回のモデル読込ではなくルールコードの読込です。

再実行結果が元と一致しない

一部の内部状態や乱数、実行条件で差が出る場合があります。画面の警告に従い、行トレースを元の実行の証拠とは扱わず、再実行時の観測として考察してください。

会話は外部へ送られる？

PyBotへの質問はPC内で処理し、サーバーは127.0.0.1だけで待ち受けます。質問を外部APIに送らず、自動保存もしません。「↓保存」操作時のみ、ブラウザからJSONをダウンロードします。
